## 项目定位

本项目希望帮助读者回答四类问题：

1. **原理**：Agent 如何选择动作、使用工具、维护上下文并结束任务？
2. **实现**：如何把模型接入实际执行环境，处理状态、权限、中断和恢复？
3. **优化**：如何通过数据、训练和 Harness 改进提高任务成功率？
4. **验证**：如何评测执行过程与最终结果，定位失败并解释方案取舍？

内容以“知识解释—实现机制—失败分析—面试追问”为主线。通用大模型基础按需补充，重点讨论它们与 Agent 系统的联系。

本项目使用 **Agent Harness** 指围绕模型建立的执行与控制系统，包括执行循环、工具接口、上下文与状态管理、权限、环境接入和恢复机制。不同项目对这一术语的边界可能不同，阅读具体实现时以其文档和代码为准。评测框架中的 evaluation harness 将在评测章节单独讨论。

## 学习路线

建议先走通一次完整任务，再逐步增加系统能力。

| 阶段 | 学习目标 | 对应实践目标 |
| --- | --- | --- |
| 1. 建立基础 | 理解 Agent、Workflow、模型与 Harness 的职责 | 画出一次任务的模型调用、工具执行和结果反馈过程 |
| 2. 实现最小循环 | 掌握工具描述、调用分发和结果回填 | 实现一个能够读取文件、执行受控命令的最小 Agent |
| 3. 维护上下文与状态 | 理解压缩、记忆、Skills 和任务状态 | 让 Agent 在多轮交互中继续未完成任务 |
| 4. 构建可恢复的 Harness | 掌握权限、事件、中断、持久化和恢复 | 处理工具超时、用户改需求及执行进程退出 |
| 5. 阅读代表项目 | 沿一次真实执行路径理解设计取舍 | 对比不同项目的循环、扩展接口和恢复机制 |
| 6. 建立优化闭环 | 理解训练、评测、归因和回归 | 在固定任务与预算下评估一次改动的效果 |

面试前可按“核心问题速答 → 原理追问 → 代码实现 → 系统设计 → 项目复盘”的顺序复习。

## Agent Harness 工程

这一部分将执行循环、上下文、工具与状态连接成完整系统，重点解释这些机制如何协同工作。

| 专题 | 需要回答的问题 |
| --- | --- |
| 架构与职责边界 | 哪些决策交给模型？哪些约束由代码执行？框架、SDK、Harness 与环境如何配合？ |
| 运行时与事件 | 如何处理流式响应、工具调度、结果回填、取消和用户追加输入？ |
| 会话与状态 | 对话记录、任务进度、工具进程状态和文件系统状态如何关联？ |
| 上下文生命周期 | 指令、Skills、记忆、工具结果何时加载、压缩、保留或移除？ |
| 执行与隔离 | 如何接入 Shell、文件、浏览器和远程环境？审批与沙箱分别约束什么？ |
| 恢复与继续执行 | 如何处理超时、崩溃、模型限流和上下文切换？如何避免重复产生外部副作用？ |
| 扩展机制 | Tools、Skills、Hooks、Plugins 分别扩展什么？依赖和生命周期如何管理？ |
| 验证与完成判定 | 如何设置验收条件？如何验证产物，识别提前结束和无效重试？ |
| 观测与重放 | 如何记录事件、工具调用和执行轨迹？哪些过程可以重放，哪些需要重新获取环境状态？ |
| Harness 优化 | 如何通过失败归因、消融实验和回归集验证一次机制调整？ |

知识点只维护一份主要解释：例如，上下文压缩原理放在第 04 章，本章讨论它如何接入运行时，项目剖析再介绍具体实现。

## 代表项目剖析

以下项目作为计划研究对象。表中列出阅读问题与研究重点；具体能力和实现方式在章节撰写时按版本核验。

| 项目 | 计划研究重点 | 面试讨论方向 |
| --- | --- | --- |
| [Codex](https://github.com/openai/codex) | Agent loop、执行事件、工具调用、审批、App Server 与交互入口 | 如何让多个客户端复用同一套 Agent 运行能力？ |
| [Claude Code](https://code.claude.com/docs/en/how-claude-code-works) | 上下文、工具、Skills、Hooks、子 Agent 与长任务机制 | 如何将工具、上下文和用户控制整合进任务循环？ |
| [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) | 插件化架构、能力组合、依赖与生命周期 | 插件化如何提高扩展能力，又会增加哪些复杂度？ |
| [Pi](https://github.com/earendil-works/pi) | 最小运行内核、扩展机制、SDK 与嵌入方式 | 最小 Harness 应包含哪些能力？哪些策略适合留给扩展？ |
| [Hermes Agent](https://github.com/NousResearch/hermes-agent) | 记忆、Skills 更新、跨会话工作与任务调度 | 如何验证经验沉淀有效，避免错误经验持续传播？ |
| [OpenClaw](https://github.com/openclaw/openclaw) | Gateway、渠道接入、会话路由、运行时与插件边界 | 长期运行的助手如何管理入口、状态和执行资源？ |

每篇剖析采用统一视角：

1. **定位与架构**：明确用户入口、模型接口、运行时、工具与环境。
2. **完整执行路径**：跟踪输入、模型调用、工具执行、反馈、验证和结束。
3. **上下文与状态**：区分模型可见信息、持久化数据和外部环境状态。
4. **扩展与控制**：说明插件、权限、用户介入和子任务如何接入。
5. **失败与恢复**：分析一条可复现的失败轨迹及其处理方式。
6. **设计取舍与追问**：讨论适用条件、复杂度、成本和替代方案。

文章标注阅读日期与版本；源码分析尽量引用固定 commit。公开资料未说明的内部实现标注为推测或待验证。教学示例用于理解机制，产品行为以其官方文档、公开代码和实验结果为依据。

## 从零实现 Harness

实践部分参考渐进式教学方法，围绕统一的小型任务集增加能力。以下为本项目的实验规划。

| 实验 | 实现目标 | 验证重点 |
| --- | --- | --- |
| `lab-01-minimal-loop` | 模型调用、工具分发与结果回填 | 一次工具调用能否形成完整反馈循环 |
| `lab-02-safe-tools` | 参数校验、权限判断、超时和错误反馈 | 参数错误与工具失败能否被识别和处理 |
| `lab-03-context-and-skills` | 按需加载 Skills、输出裁剪与历史压缩 | 压缩后能否保留目标、约束和关键执行结果 |
| `lab-04-state-and-memory` | 任务状态持久化、会话恢复与记忆检索 | 新会话能否继续任务，错误或过期记忆能否处理 |
| `lab-05-background-and-recovery` | 后台执行、取消、恢复与重复操作防护 | 中断后是否丢任务，是否重复执行外部操作 |
| `lab-06-delegation` | 子 Agent、上下文隔离、结果汇总与资源协调 | 委派是否改善任务结果，通信和并发代价是否可接受 |
| `lab-07-integrated-harness` | 整合扩展点、任务状态与产物验证 | 多个机制是否能够在一次完整任务中协同工作 |
| `lab-08-evaluation-loop` | 固定任务集、轨迹记录、失败归因与消融 | 一次改动的收益能否重复出现，是否引入回归 |

实验代码计划放在 `examples/`，相应原理和复盘放在知识章节中。运行说明需注明依赖、模型配置、环境要求、预期结果和失败示例。

系统设计案例计划包括：

- **Search Agent**：查询分解、多轮搜索、证据组织、引用和停止条件。
- **Coding Agent**：仓库理解、文件修改、测试反馈、变更检查与任务交付。
- **Agent 评测系统**：测试集、工具模拟、执行轨迹、产物验证、错误分类与回归报告。

案例按“目标与约束—基线—失败证据—方案调整—评测结果—局限”组织。

## 面试题与文章规范

正文面向理解与实践，面试索引提供复习入口。同一问题的主要答案只维护一处。

### 单篇文章结构

| 部分 | 内容要求 |
| --- | --- |
| 核心问题 | 明确文章要解释的问题和必要前置知识 |
| 30 秒回答 | 给出能够直接口述的主要结论 |
| 原理展开 | 解释机制，按需使用公式、图示和执行轨迹 |
| 最小实现 | 提供短代码、伪代码或可运行示例，标清性质 |
| 设计取舍 | 说明适用条件、代价、限制和替代方案 |
| 失败分析 | 说明失败表现、定位依据和处理方式 |
| 面试追问 | 从概念逐步深入实现、优化与系统设计 |
| 参考资料 | 列出原始论文、官方文档、代码来源及版本信息 |

### 首批问题方向

- Agent 与固定工作流如何选择？两者如何在同一系统中配合？
- 模型生成工具调用后，系统需要完成哪些步骤？
- Function Calling、MCP 和 Skills 分别解决什么问题？
- 上下文压缩后，如何继续一个尚未完成的任务？
- 对话历史、任务状态、长期记忆和 Skills 有什么区别？
- 用户执行途中更改需求时，哪些步骤需要取消或重新规划？
- 工具超时后，如何判断操作是否已经成功并避免重复执行？
- 单 Agent、子 Agent 委派与多 Agent 团队分别适合什么场景？
- 如何判断任务真正完成，而不只依赖模型的结束声明？
- 为什么同一个模型在不同 Harness 下可能表现不同？
- 如何构造 Agent 训练轨迹，并处理长任务中的奖励与信用分配？
- 如何区分模型、工具、环境和 Harness 导致的失败？

训练与评测会特别关注：工具接口与反馈格式、上下文处理和运行策略变化，是否造成训练与部署之间的分布差异；评测时如何记录并控制模型、任务环境、权限、预算和随机性。
